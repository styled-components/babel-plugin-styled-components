---
'babel-plugin-styled-components': patch
---

A binding that is the styled factory keeps display names and component ids for properties this plugin does not recognize. On styled-components v7 that factory is a proxy, so `styled.box`, `styled.foo`, and `styled.feNotAFilter` are real components. `const styled = require('styled-components')`, `import sc from 'styled-components'`, `sc.default`, `ns.default`, and `__importDefault(require('styled-components')).default` are that factory. Known non-tag exports and object methods stay plain, including `sc.css`, `sc.keyframes`, `sc.createGlobalStyle`, `sc['createGlobalStyle']`, `sc.isStyledComponent`, `sc.hasOwnProperty`, `sc.toString`, and `sc.default.css`. A computed key is resolved when it is a string, a template with no interpolation, or a const initialized to one of those, so `const name = 'css'; sc[name]` and `` sc[`css`] `` stay plain. A key the plugin cannot resolve is still decorated, and that throws if the runtime value is a helper. A `let` or `var` that starts as the factory and is reassigned later keeps its display name on uses written before the reassignment. Uses written after it are left alone.
